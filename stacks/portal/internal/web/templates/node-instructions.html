1 · Waiting for connection

WAITING Waiting for cloudflared from this machine to connect… checked every 3 seconds.

As soon as a new connection shows up, the portal binds it to the name {{.Name}} and opens the node list.

2 · Pick a connection method

Use when: the machine already runs Docker — VPS, Raspberry Pi OS, mini PC, home server. The container auto-restarts and upgrades are just an image swap. Fits most home nodes.

docker run
{{.DockerCmd}}

The token is a secret — never paste it in a public chat. Container network: make sure the node machine can reach the chosen origin (e.g. {{.Origin}}).

Use when: the machine has no Docker, a production server that needs systemd, or a non-Linux OS. The binary is tiny — run it as a service so it comes back after reboot. Fits small VPS and fully managed machines.

install binary + service
{{.BinaryCmd}}

Swap linux-amd64 for linux-arm64 on ARM machines (Raspberry Pi 4/5 64-bit).

3 · After it connects

  • The node shows up in the node list with status CONNECTED.
  • In the hostname form, this node can be picked in the Connector / node column — the origin fills in automatically.
  • Connection dropped? The portal marks it OFFLINE; if cloudflared restarts with a new client_id, a Rebind to … button appears.
